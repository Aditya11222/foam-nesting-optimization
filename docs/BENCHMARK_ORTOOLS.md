# Benchmark Report: Google OR-Tools vs Custom Slicing-Tree Heuristics

> **Demo & Benchmark Disclaimer**: All benchmark metrics are calculated on synthetic production datasets. 
> Google OR-Tools CP-SAT proves mathematical optimality only for the combinatorial allocation and pattern-selection model. 
> Physical 3D cutting layout and cutting sequences are generated by the custom orthogonal slicing tree heuristic.

## 1. Executive Summary

This benchmark evaluates 5 distinct optimization strategies on **Tatras NestPro** across four test suites:
1. **Best-Fit Decreasing (BFD)**: Greedy volume sort with orthogonal slicing tree.
2. **First-Fit Decreasing (FFD)**: Fast first-fit leaf search.
3. **Simulated Annealing (SA)**: Stochastic permutation search.
4. **OR-Tools Block Assignment (ORT-ASSIGN)**: CP-SAT multi-bin allocation with iterative verification loop and cardinality cuts.
5. **OR-Tools Pattern Selection (ORT-PATTERN)**: Fixed-pool column generation solving integer pattern frequencies.

## 5. Honest Analysis: Where OR-Tools Helps and Where It Does Not

### Where OR-Tools Delivers Clear Value
1. **Multi-Bin Allocation (ORT-ASSIGN)**:
   - On multi-block orders, standard greedy heuristics (BFD) pack the first bin aggressively, often stranding awkward remainders in the final bin.
   - OR-Tools CP-SAT balances volume across candidate blocks simultaneously, heavily prioritizing existing warehouse remnants before virgin buns.
2. **Guillotine Feasibility Verification**:
   - The iterative verification loop with cardinality cuts successfully prevents physical packing failures.
3. **Automated Machine Selection (Auto OR-Tools)**:
   - Multi-objective machine routing selects optimal stations based on cost, saw time, and kerf loss while guaranteeing throat height feasibility.

### Where OR-Tools Does NOT Beat Classical Heuristics
1. **Single-Bun / Low-Count Jobs**:
   - When an entire order fits easily into 1 standard bun, BFD and FFD solve the problem in under 5 ms with near-identical yield to OR-Tools.
   - Running CP-SAT on trivial single-block orders introduces unnecessary solver setup overhead.
2. **Fixed-Pool Pattern Limitations (ORT-PATTERN)**:
   - Because ORT-PATTERN selects from a fixed pre-generated pool of candidate patterns (rather than dynamic Gilmore-Gomory pricing), highly idiosyncratic part geometries can yield higher density when explored via Simulated Annealing or BFD.
3. **Pure Physical Optimization**:
   - OR-Tools is solving the mathematical allocation model. The physical layout is still constructed by the slicing tree. Proving mathematical optimality of the allocation model does not prove physical global optimality of the 3D packing.
